01 / What I wanted to investigate

Make electricity market data easier to explore

Germany's hourly electricity market data can be used to investigate renewable generation, grid demand and wholesale day-ahead prices. I built a dashboard that makes these observations easier to explore while preserving missing data and source limitations.

The application is descriptive, not predictive. It does not explain household electricity bills or prove that changes in one generation source cause changes in prices.

Questions the dashboard supports

  • How did day-ahead wholesale prices change over the selected period?
  • When did hourly wholesale prices fall below zero?
  • How did the observed generation mix change?
  • How did high wind and solar output hours compare with other hours?
  • How complete are the underlying observations?

The Python ingestion module discovers indexed SMARD data blocks, retries transient HTTP failures and assembles an hourly UTC grid. Any unavailable readings remain missing rather than silently becoming zero. The data can also be stored through a reproducible SQLite snapshot.

The public GitHub Pages version uses a scheduled GitHub Actions process to publish a static snapshot. Its “Check for new data” button checks for a newer published snapshot, not a live API call or a fresh workflow run.

03 / Analytical logic

Completeness before calculation

The dashboard reports renewable generation share only for hours when all eleven generation categories have observations. The denominator is total observed generation for those fully covered hours, not national electricity consumption.

Show the completeness rule from the Python implementation
df["generation_complete"] = (
    df[list(GENERATION)].notna().all(axis=1)
)
df["renewable_pct"] = np.where(
    df["generation_complete"] & df["generation_mwh"].gt(0),
    df["renewable_mwh"] / df["generation_mwh"] * 100,
    np.nan
)

Missing prices are also excluded from price averages. The dashboard displays coverage by market series so a visitor can judge how much data supports a chart.

04 / Time and data quality

Hourly reporting needs careful time zones

SMARD timestamps are stored in UTC. The dashboard converts them to Europe/Berlin for presentation. At the autumn daylight-saving change, two observations can share the same local clock hour. The calendar display merges repeated hours for the heatmap only; source observations remain separate.

Coverage reporting

Missing hourly observations are counted and described rather than filled with fabricated values.

Automated tests

Tests cover negative-price hours, renewable share, missing solar values and the spring daylight-saving transition.

05 / Choices and limitations

What the project demonstrates

The repository contains Python ingestion, descriptive analytics, local SQLite storage and a separate Streamlit application, as well as the static HTML/JavaScript dashboard published on GitHub Pages.

  • Transparency: show incomplete observations instead of pretending everything was measured.
  • Reproducibility: retain the transformation logic in source control and test it with known input fixtures.
  • Source context: distinguish wholesale market prices (EUR/MWh) from consumer electricity bills.
  • Conservative interpretation: a statistical association between wind/solar output and price does not establish causation.
  • Operational limits: data refresh depends on upstream SMARD availability and the GitHub Actions schedule, which can be delayed.
Market data comes from Bundesnetzagentur's SMARD platform, under its published data-use terms. This independent project is not endorsed by the provider.
